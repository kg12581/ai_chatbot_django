# 埋点功能变更说明

> 变更时间：2026-08-02　|　方案：A（自建轻量埋点，不用 Kafka）　|　状态：已实现并在线验证

## 一、变更概述

新增一套自建埋点统计能力，覆盖前端页面访问与用户行为，数据存入项目自身的 MySQL，
并提供统计页面、Admin 后台与 CSV 导出。设计为“轻量、可切换”：上报接口与表结构独立，
后续若数据量增大可平滑替换为 Kafka 等消息队列（接口不变）。

## 三、功能架构与数据流

```mermaid
flowchart LR
    A[浏览器页面] -->|自动 PV| B[POST /api/track/]
    A -->|data-track 点击| B
    A -->|window.trackEvent 手动| B
    B -->|参数清洗/入库| C[(MySQL analytics_event)]
    C --> D[/analytics/ 统计页]
    C --> E[Admin 后台]
    C --> F[export_analytics CSV]
```

前端不阻塞：使用 `navigator.sendBeacon`（降级为 `fetch keepalive`），页面关闭/跳转时也能送达。

## 四、数据模型（表结构）

`analytics_event` 表字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_type` | varchar(20) | 类型：pageview / click / action / error |
| `event_name` | varchar(100) | 事件名（带索引） |
| `page_url` | varchar(500) | 页面地址 |
| `user` | FK | 登录用户（可空，匿名也有） |
| `session_key` | varchar(100) | 会话（用于 UV 去重，带索引） |
| `ip` | GenericIPAddress | 客户端 IP（支持 X-Forwarded-For） |
| `user_agent` / `referrer` | varchar(500) | UA / 来源 |
| `payload` | JSON | 自定义参数（已清洗） |
| `created_at` | datetime | 事件时间（带索引） |

## 五、上报接口

`POST /api/track/`（支持登录与匿名，CSRF 豁免）

请求体：

```json
{
  "event_type": "click",
  "event_name": "douyin_crawl",
  "page_url": "/api/douyin/hot/",
  "payload": { "source": "page" }
}
```

参数规则：

- `event_name` 必填，最长 100
- `event_type` 非法值自动回退为 `action`
- `payload` 清洗：最多 20 个键、字符串截断 200 字符、非标量（数组/对象）丢弃
- 返回 `{"success": true}`；请求体非法 JSON 或缺 event_name 返回 400

## 六、前端埋点用法

`tracking.js` 已全局引入，无需额外初始化：

```html
<!-- 1. 自动绑定：任意元素加 data-track，点击自动上报 -->
<button data-track="chat_send" data-track-payload='{"type":"text"}'>发送</button>
```

```javascript
// 2. 手动上报
window.trackEvent("douyin_crawl", { source: "page" });
```

页面 PV 在 DOMContentLoaded 时自动上报（事件名 `pageview`）。

## 十、注意事项与后续扩展

1. `analytics_export.csv` 为导出产物，建议加入 `.gitignore`
2. 当前为直写 MySQL；若后续量增大，可在 `track_event` 视图内切换为 Kafka 生产者，
   由独立消费者批量入库（表结构无需变更）
3. UV 按“会话 + 用户”去重，同一浏览器多标签页算一个会话；如需更精确可接入 Cookie 指纹
4. 埋点数据属于个人信息范畴，正式上线前需评估隐私合规（脱敏、留存期限、用户可关闭）
